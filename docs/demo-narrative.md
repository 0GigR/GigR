# Demo narrative

Speak this. It is written to be said out loud, in order, and every claim is true
of the deployed build.

## 1. What Gigr is (15s)

"Gigr is a marketplace for local services. You need a plumber, a tailor, a phone
repair; you find one, you agree a price, and the money sits in escrow until the
work is done. The escrow matters because both sides are strangers."

## 2. The agent (15s)

"On top of that sits Gigidy, an AI agent. You talk to it in plain language and it
does the work: finds the provider, drafts the request, holds the budget, and
tracks the job. The point is that a user should not have to fill in a form to
hire a plumber."

## 3. The flaw (25s)

"Here is the problem we hit. The agent was stateless. Every conversation started
from nothing, so the agent asked again what it should already know: your budget,
your area, whether you had hired this person before and what happened. A user
repeats themselves every session, and the agent cannot learn from a bad job
because it does not remember the last one.

We were storing a little of it in a JSON column. That is not memory. It is a
settings table. It cannot be searched by meaning, it dies with the database, and
it belongs to the platform rather than the person."

## 4. What we did (30s)

"We replaced it with Walrus Memory. Each user gets their own namespace on
Walrus, and facts about them are written there as sentences: your budget, your
area, the jobs you posted and how they ended, your ratings, your disputes.

Two design decisions matter. First, the facts are extracted from rows by
templates, never generated by a model. If a field is missing, no fact is written.
A model would have guessed, and a guessed memory is worse than no memory.

Second, recall is by meaning, not by key. The agent asks Walrus for what is
relevant to the question and gets back sentences, scored. That is the difference
between a settings table and a memory."

## 5. Why Walrus specifically (25s)

"Three reasons. It belongs to the user, not to our database: the memory survives
the app. It is content-addressed and replicated, so it is not one Postgres row
away from being lost. And because a blob lives as an object on Sui, it can be
verified on chain rather than taken on trust.

That last part is the one I want to show you, because it is the part you cannot
fake."

## 6. The proof (40s)

Open the memory page, scroll to Prove it on chain. Click Verify.

"This checks a Walrus blob object on Sui. Object type, version, owner, certified
epoch. This is not our database saying so, it is Sui."

Then open an explorer on a second screen:

https://suivision.xyz/object/0x0000003c64bf4bda578d911acb4f93f470a89f66d9fd8993fdb032cf007b1c93

"And here is the same object on a public Sui explorer, in a browser we do not
control. Same type, same version. You do not have to believe the app."

If you want the strongest version, run this live in a terminal:

    curl -s -X POST https://graphql.mainnet.sui.io/graphql \
      -H 'Content-Type: application/json' \
      -d '{"query":"{ object(address: \"0x0000003c64bf4bda578d911acb4f93f470a89f66d9fd8993fdb032cf007b1c93\") { version asMoveObject { contents { type { repr } } } } }"}'

"That is Sui's own public GraphQL endpoint, not our server, not Tatum. Same
version, 810023862."

Note for you, not to say on camera: Sui has deprecated public JSON-RPC and tells
people to use gRPC or GraphQL. That is exactly why the Tatum integration speaks
gRPC, and it is a good answer if a judge asks why not JSON-RPC.

## 7. Deletion, and why it is interesting (35s)

Scroll to the delete controls.

"Here is where the design gets honest. Walrus is immutable by design. A blob is
an object; you cannot edit one field of it. The SDK can delete a namespace, and
that is all-or-nothing.

But users do not want all-or-nothing. They want to forget one thing, or correct
one thing. So we built it the only way that is correct on top of an immutable
store: read everything, work out what should remain, delete the namespace, and
write the remainder back to a new one.

The dangerous part is the gap between the delete and the rewrite. If the process
dies there, the user has lost everything. So before we delete anything we write
the exact list of what must be restored to a journal on disk, and every later
operation finishes that restore before doing anything else. There is a test that
kills the process mid-rewrite and proves a new instance repairs it.

We also raised this upstream. The Python SDK had no delete at all, so we filed
it, and it shipped in memwal 0.2.2. That is why the button exists now."

## 8. Tatum (25s)

"Tatum sits on both chains, and we use it deliberately differently.

On Solana, reads go through Tatum's RPC gateway. Writes never do. Routing a
transaction through a third party is how you break escrow, and we learned that
the hard way. So reads are the integration and writes stay on our own path.

On Sui, verification goes through Tatum's Sui gateway. That one is gRPC only:
Tatum's Sui JSON-RPC endpoint does not exist, and Sui itself has deprecated
JSON-RPC in favour of gRPC and GraphQL. We speak gRPC."

## 9. Agent payments (30s)

"A marketplace of agents is the next step: another agent should be able to buy
intelligence from Gigr without a human signing up.

We built that with x402, the HTTP 402 payment scheme. An agent asks for a brief
on a job. Instead of a login wall it gets a 402 with a price in USDC, a recipient
and a nonce. It pays on Solana, retries with the settlement signature, and we
verify that transaction on chain, checking the mint, the recipient, the amount
and that the signature has not been spent before. One payment buys one brief.

Show the card, which is labelled QUOTE, NOT A PAYMENT.

"What I am showing is the quote, not a purchase, because a purchase needs a
funded devnet wallet and I would rather show you the real challenge than stage a
fake transaction. The verification path is tested against the case that matters
most: a payment in the wrong token is refused. A worthless token is not USDC,
and the endpoint says so."

Note for you: x402 does not support Sui; its supported networks are EVM, Solana,
TON, Algorand, Stellar, Aptos, Hedera, Keeta, NEAR, Concordium, XRPL and Cardano.
Say "on Solana" and do not claim Sui settlement.

## 10. Close (15s)

"Gigr is a marketplace with an agent that remembers you. The memory is on Walrus,
it belongs to the user, it can be verified on chain, and it can be deleted
honestly. Everything I showed is running now, and there are 396 backend tests and
143 frontend tests behind it."

## If a judge asks

- **Is the memory really on Walrus?** The agent panel says how many memories it
  recalled from Walrus. The proof card reads a blob object on Sui.
- **What if Walrus is down?** The page says "from local storage" and the agent
  still works. We never claim a recall that did not happen.
- **Can you delete one memory?** Yes, by rewriting the namespace. The confirmation
  says so, including that kept memories are re-saved with today's date.
- **Why not a vector database?** A vector database is ours. Walrus memory belongs
  to the user, is content-addressed, and is verifiable on chain.
